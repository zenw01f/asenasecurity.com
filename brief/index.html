Lead storyHighPassword management · Supply chain · GitHub

1Password discloses breach via compromised employee GitHub account; customer names, cryptographic tokens, and internal source code stolen — password vaults remain secure

An attacker accessed 1Password's backend services by injecting malicious code through a corporate GitHub account, exposing account metadata and infrastructure credentials in a targeted compromise of a trusted security tool.

On November 25, 1Password disclosed that an unauthorized party compromised an employee's GitHub account on November 19 and used it to inject malicious code into the company's backend services. The company confirmed that stolen tokens allowed the attacker to extract customer account metadata including names, email addresses, account IDs, public cryptographic keys, Secure Remote Password parameters, and account provisioning and recovery tokens. The company's CI/CD environment was also accessed, and internal source code was stolen. 1Password moved quickly to disable the compromised account, revoke the stolen tokens, restore clean service versions, and rotate or revoke exposed infrastructure credentials. It strengthened account verification codes from six numeric digits to ten alphanumeric characters as part of its remediation.

Customer password vaults and the master passwords that protect them were not compromised — 1Password's end-to-end encryption architecture ensures vaults are encrypted on-device before being stored, and the stolen tokens cannot independently unlock them. However, the exposed provisioning and recovery tokens are valuable to attackers as phishing material: they can be used to craft convincing password-reset requests targeting 1Password users, and the full roster of confirmed customer accounts is a targeting list for credential-stuffing campaigns at every organization using the product. 1Password individually notified affected users and hired independent forensic investigators to validate the response.

The incident fits a pattern of attackers targeting developer identity and CI/CD pipelines as a supply-chain pivot point. A compromised employee GitHub account provides access not just to source code but to secrets embedded in workflows, deployment configurations, and integration tokens — which is why the CI/CD environment access is the operationally significant detail here, even more than the customer metadata. The stolen signing and infrastructure credentials have been rotated, but any customer using 1Password's APIs or deeply integrating with the product's provisioning layer should audit their own access logs for the November 19 window.

Why it matters: Enable phishing-resistant MFA on all 1Password accounts and brief end users to be alert for password-reset phishing over the next 90 days — the confirmed customer email list makes this population a known target. For organizations integrating 1Password via API or provisioning tokens, review access logs for the November 19–25 window and re-verify that rotated credentials are propagated across all dependent pipelines.

HighEnterprise software · Supply chain · GitHub

SAP confirms security incident after attackers steal employee GitHub tokens and copy source code; signing keys rotated and automated development pipelines suspended across the company

SAP confirmed it detected suspicious activity in its GitHub environment after threat actors obtained authentication tokens belonging to SAP employees and used them to access and copy source code from the company's repositories. SAP responded by replacing its code-signing keys, restricting GitHub access, and suspending automated development pipelines across numerous teams — disrupting developer workflows company-wide while the investigation continues.

SAP stated it found no evidence of unauthorized access to customer business data and no indication that any compromised code was incorporated into software delivered to customers. The specifics of which repositories were accessed — whether proprietary SAP application code or the developer tools and sample applications SAP publishes publicly on GitHub — have not been disclosed. The signing-key rotation is the operationally significant response: SAP's code-signing infrastructure protects the integrity of software updates and SDK releases delivered to enterprise customers, and rotating those keys is a precautionary step to ensure that any attacker who accessed repositories cannot leverage stolen keys to sign malicious software presented as a legitimate SAP update.

Why it matters: IT teams managing SAP update pipelines should confirm that automated deployment tools accept SAP's new signing keys without error. Organizations using SAP's developer tools, GitHub-hosted SDKs, or the SAP BTP platform should validate the integrity of any packages fetched from SAP's GitHub during and immediately following the November 19–27 window.

CriticalWeb CMS · RCE · KEV · Active exploitation

Two distinct critical Drupal vulnerabilities — CVSS 9.8 Fail2Install (federal deadline today) and new access-bypass CVE-2026-136716 — are both under active exploitation simultaneously

CISA added the Drupal Fail2Install flaw (CVE-2026-132165, CVSS 9.8) to its Known Exploited Vulnerabilities catalog on November 24 with a 72-hour federal remediation deadline of November 27. The vulnerability exploits resource exhaustion to trick Drupal's installation checks into believing a live site is uninstalled, reopening install.php — once accessible, attackers can redirect the database to an attacker-controlled server, create administrator accounts, and execute arbitrary PHP code. Active exploitation has been confirmed since November 19; patches exist in Drupal 10.6.22+, 11.3.22+, and 11.4.13+.

On November 27, Drupal's security team disclosed a second critical vulnerability — CVE-2026-136716, a separate access-bypass flaw — with an emergency advisory confirming active exploitation on the same day it was published. The two flaws are distinct vulnerabilities that require separate patches and are being exploited simultaneously in the wild. Organizations running any version of Drupal 8, 9, 10, or 11 face a double-patching emergency: a SecurityWeek analysis notes the second flaw was introduced as a byproduct of an earlier incomplete installer patch, meaning some sites that thought they were secured remain exposed.

Why it matters: Drupal powers a significant share of government, university, and enterprise web properties. If clients or their vendors manage Drupal deployments, emergency patching is required now — the federal CISA deadline for Fail2Install was today (Nov 27). Extend the check to third-party web development firms managing CMS deployments on a client's behalf; they may not have patching on the same cadence as internal IT.

HighKEV · Mitel · Juniper · Multi-vendor

CISA adds 10 exploited vulnerabilities in a single alert, including five Mitel MiCollab zero-days exploited in AI-assisted attacks before disclosure and a critical root-RCE flaw in Juniper Session Smart

CISA issued an alert on November 25 adding 10 newly catalogued exploited vulnerabilities to its Known Exploited Vulnerabilities database — one of the larger single-day additions in recent months. The batch includes five zero-day flaws in Mitel MiCollab unified communications systems, which Accenture researchers discovered had been exploited before vendor disclosure in what SecurityWeek describes as a suspected AI-assisted extortion campaign, with attack types including arbitrary file upload and XML injection. Juniper's Session Smart Conductor also received a KEV entry for CVE-2026-103406, allowing remote attackers to execute arbitrary commands as root on affected systems.

Two GeoServer vulnerabilities (CVE-2026-120705 and CVE-2026-129243) are also included, enabling chained unauthenticated remote code execution against the geospatial data server used in government and utilities environments. The Mitel and Juniper exploitations are particularly notable: Mitel MiCollab is a widely deployed unified communications platform, and AI-assisted threat actors leveraging zero-days before vendor disclosure signals automated reconnaissance of enterprise UC infrastructure at scale. For Juniper Session Smart Conductor, the root-RCE designation means a successful attack yields complete control of the routing and SD-WAN management plane.

Why it matters: UC systems and SD-WAN routers rarely get the same patching urgency as endpoints and cloud workloads, but this batch shows they are actively targeted. Run an asset inventory check for Mitel MiCollab, Juniper Session Smart, and GeoServer in client environments, and prioritize patching for any internet-facing instances.

HighSupply chain · North Korea · Developer targeting · Blockchain C2

North Korea-linked PolinRider poisons 7,600 GitHub repositories with a Python loader hidden in build configs, using Ethereum blockchain transactions as command-and-control to evade blocking

Apiiro researchers published an analysis of PolinRider, a North Korean malware distribution campaign assessed as a sub-cluster of the broader Contagious Interview operation. Attackers stole GitHub authentication tokens from compromised developer machines and used them to force-push malicious commits into more than 7,600 repositories across 2,330 accounts between October 27 and November 6. The poisoning technique is unusually stealthy: attackers rewrote existing developer commits — keeping the original author, message, and timestamp intact — and appended a 58-line Python loader hidden after hundreds of spaces in build configuration files. Some 86% of affected repos belong to personal accounts more than a year old with genuine commit histories.

The Python loader retrieves its second-stage payload from Ethereum blockchain transactions — a command-and-control technique that makes the C2 infrastructure exceptionally difficult to block since it operates over the public Ethereum network. The loader scans for developer tools including GitHub Desktop, VS Code, and Cursor, then delivers an infostealer targeting environment secrets, passwords, and cryptocurrency wallets. Projects confirmed to have been compromised include Neutralinojs, InstaWP Connect, and fxhash. Blockchain analysis traces related activity as far back as February 2025, suggesting this infrastructure has been operational for well over a year.

Why it matters: Developer environments are targeted specifically because they hold production secrets, cloud credentials, and code-signing keys. Audit internal developer toolchains for any GitHub repository that received an unexpected push during October 27–November 6, verify that no modified build configurations entered CI/CD pipelines, and check whether any developer machines show signs of the PolinRider infostealer. The blockchain C2 means network-layer blocking is not sufficient — detection must come from endpoint and pipeline integrity checks.

HighCritical infrastructure · AI-assisted · Switzerland · Multi-sector

Switzerland confirms four of five AI-assisted attacks achieved breaches, with three hitting critical infrastructure operators; autonomous frameworks switched tactics in real time to defeat defenses

Switzerland's National Cyber Security Centre confirmed five AI-assisted cyberattacks in a security advisory this week, reporting that four of the five penetrated targeted systems and three successfully breached critical infrastructure operators — including electricity suppliers, drinking water utilities, and telecommunications providers. Victim identities were not disclosed. Swiss authorities described the attacks as using "agentic offensive frameworks": autonomous AI agents that scan for unpatched vulnerabilities, execute attacks across multiple targets in parallel, and adapt their approach in real time when defenses respond. Italy's CSIRT documented similar mass-compromise campaigns in the same advisory period.

Swiss authorities named ARTEX and CyberStrikeAI as examples of publicly available agentic attack tools, though officials did not confirm these specific tools were used in the five incidents. The UK NCSC had previously documented the broader rise of AI-assisted attacks (covered in Edition #006); the Swiss confirmation of real successful infrastructure breaches — not theoretical risk — represents an escalation of that reporting from advisory to confirmed incident with named sectors. Key defensive recommendations from the Swiss advisory: patch critical internet-facing systems within 24 hours of disclosure, reduce direct internet exposure via authentication and geo-blocking, and enforce MFA across all remote access.

Why it matters: This is the first official multi-country confirmation of AI-assisted attacks achieving documented breaches of critical infrastructure systems, extending the threat from cautionary warning to recorded reality. For clients in energy, utilities, water, and telecom, the 24-hour patching cadence recommendation from Swiss authorities is now operationally grounded — and the compressed window between vulnerability disclosure and AI-driven exploitation means slow-patching environments face a materially higher risk than they did 12 months ago.

CrowdStrike closes holiday week at $209 as the market absorbs the Zscaler deal; VIX falls sharply from 30.87 to 25.37 and Friday pre-market futures point higher across the board

After CrowdStrike's strong Q3 earnings triggered a 4.3% pre-market drop in the previous edition — as investors weighed integration risk from the $43.9 billion all-stock Zscaler acquisition against a volatile tape — the company closed Wednesday at $209.30 (a -0.74% daily change) as selling pressure faded through the session. With markets closed Thursday for Thanksgiving, Friday pre-market data shows CRWD recovering to $211.88 (+1.23%) and broader market futures pointing higher: S&P +1.54%, Nasdaq +2.18%, Dow +1.31%. The VIX, which spiked to 30.87 on Wednesday, fell to 25.37, suggesting the volatility overreaction to the week's earnings is easing.

The CrowdStrike/Zscaler deal is expected to close in the second half of CrowdStrike's fiscal year 2028, leaving 18+ months for integration planning. CEO George Kurtz characterized the combination as building "cybersecurity's operating system: a single control plane to deploy AI, control AI, and enable any agentic application to run safely." Analyst targets on CRWD range from $174 (bear case) to $320 (bull case), with the ongoing debate centering on whether the platform thesis can outcompete Palo Alto Networks' established multi-product consolidation strategy. The VIX normalization and CRWD pre-market recovery both suggest the institutional market is settling into a more analytical read of the deal.

Black Friday: abbreviated session closes at 1 PM ET with futures up 1.5–2.2%; semiconductors lead pre-market as holiday-week thin trading amplifies moves

US equity markets reopened Friday for a holiday-shortened session closing at 1 PM Eastern time after Thanksgiving kept traders out Thursday. Pre-market futures pointed sharply higher — S&P 500 futures +1.54%, Nasdaq 100 futures +2.18%, Dow futures +1.31% — after Wednesday's indices ended slightly negative (S&P 500 -0.25% at 7,182.78; Nasdaq -0.62% at 23,585.80). Semiconductors led pre-market gains: SanDisk +10.87%, Micron +6.1%, AMD +4.4%. Holiday-week trading volume tends to be thin, amplifying percentage moves in both directions.

Treasury yields were flat at 4.90% on the 10-year after the week's volatility, and Bitcoin recovered to $61,365 (+0.93%). No major economic data releases were scheduled for Black Friday. The next significant market catalysts will be the November jobs report (December 5) and the Federal Reserve meeting (December 10–11). Thin holiday markets can amplify the equity impact of any cyber-incident news surfacing over the weekend — a pattern that has contributed to some of the larger post-breach stock moves in recent years, particularly in retail and financial services.
