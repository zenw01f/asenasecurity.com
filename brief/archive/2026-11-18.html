Lead storyCriticalVulnerability · Java · KEV

Java4Shell (CVE-2026-114938): Critical pre-auth RCE in OpenJDK affects Jira, Jenkins, Keycloak, Confluence, and dozens more enterprise apps

A buffer overflow in Java's AVX-512-optimized Base64 decoder lets unauthenticated attackers execute code on servers running the most common enterprise Java platforms; Oracle shipped emergency patches and CISA is urging immediate action.

The vulnerability, dubbed Java4Shell and tracked as CVE-2026-114938, lies in an AVX-512-optimized Base64 decoding routine used by Java 17, 21, 25, and 27 on x86-64 processors that support the AVX-512 VBMI instruction set — Intel Xeon Ice Lake and newer, AMD Zen 4 and newer. A malformed Base64 string with a trailing equals sign causes the decoder to write 62–63 bytes past the end of an output buffer, corrupting heap memory in a way researchers turned into unauthenticated remote code execution. Demonstrated pre-auth targets include Keycloak, Jira, Confluence, Artifactory, Jenkins, and PingFederate; authenticated RCE is additionally possible against Apache Kafka, Solr, Elasticsearch, Gerrit, and Spinnaker. ARM64 is not affected. CVSS scores range from 8.1 (Oracle) to 9.8 (preliminary, Red Hat), with an independent assessment at 9.2.

Oracle released fixes November 18 as part of its November 2026 Critical Security Patch Update, covering Java 17.0.21.1, 21.0.13.1, 25.0.5.1, and 27.0.1.1. Amazon Corretto and Azul Zulu have also shipped updated builds; Red Hat errata were pending. CISA published an advisory urging immediate patching of internet-exposed systems and added CVE-2026-114938 to the Known Exploited Vulnerabilities catalog. Cisco Talos expects probing to increase now that the vulnerability is public. No confirmed in-the-wild exploitation had been reported as of publication.

Researchers also describe a secondary capability they call "JavaBleed": by tuning the heap corruption to read rather than overwrite adjacent memory, an attacker can extract in-process secrets — session tokens, PII, and cryptographic keys — without fully compromising the host. Organizations running containers, appliances, or vendor software with an embedded JRE should inventory their Java versions immediately; a workaround JVM flag (-XX:-UseBASE64Intrinsics) disables the vulnerable code path without a full upgrade.

Why it matters: Jira, Confluence, and Keycloak are identity and collaboration cornerstones for most enterprise environments, and they are frequently internet-facing. The gap between Oracle's patch and vendor-specific updates (Red Hat, container images, appliances) means many organizations are waiting on third-party timelines they don't control. Apply the -XX:-UseBASE64Intrinsics workaround immediately on any exposed system while waiting for patched builds, and treat this like Log4Shell in terms of breadth of inventory needed.

Cyber × Supply ChainCriticalPyPI · Azure · GitHub

Microsoft's agent-framework PyPI package poisoned overnight; malware silently drained Azure and GitHub credentials from 190,000 monthly downloaders

Attackers published two malicious versions of Microsoft's agent-framework PyPI package — 1.26.1 and 1.26.2, released 33 minutes apart on November 17 — that installed Python startup hooks exfiltrating Azure CLI tokens, Azure DevOps OIDC tokens, managed-identity credentials, Azure instance-metadata, GitHub Actions OIDC tokens, plus npm, pip, Docker, and Hugging Face secrets to an attacker-controlled webhook endpoint. Because the hooks fired at Python startup, any process using the Python interpreter on an affected system ran the stealer automatically, even without explicitly importing the package. PyPI quarantined both versions after multiple security firms raised the alarm.

The package receives roughly 190,000 downloads a month and is widely used in CI/CD pipelines and developer environments building AI agents on Azure. Discoverers include Aikido, Chainguard, Endor Labs, OX Security, SafeDep, Socket, StepSecurity, and Wiz. Version 1.26.0 is the last clean release. Organizations should check developer workstations, container images, and pipeline runners for the compromised versions; rotate all Azure and GitHub secrets from clean systems; and audit Azure identity activity logs and GitHub workflow run logs for signs of exfiltration. Rebuilding affected environments is preferable to patching in place.

Why it matters: AI-agent development has pushed credential exposure into a new tier of risk — cloud identity tokens are the keys to entire tenants, not just individual accounts. Any client building on Azure with AI frameworks should require pinned dependency versions, verify package integrity at install time, and treat CI/CD runners as credential vaults that need scoped, short-lived tokens.

CriticalSkimmer · 178 Sites · Finance

Attackers injected a multi-function skimmer into Optimizely's Web Experimentation platform, hitting 178 customer sites including 32 banks and finance companies

The Record reports that hackers placed malicious JavaScript inside Optimizely's Web Experimentation platform, spreading it to roughly 178 widely visited customer websites identified by Report URI. The injected code acted as a multi-purpose toolkit: it swapped cryptocurrency wallet addresses to redirect funds, skimmed payment-card data, stole browser cookies and screenshots, and delivered two iOS exploit kits (Coruna and DarkSword) to Apple device visitors. Blockchain analysis confirmed at least $7,000 in cryptocurrency theft. At least 32 finance and banking sites were among those affected, alongside technology, news media, airline, and retail platforms. Optimizely said it "identified and contained" the incident after the latest campaign on November 17; the threat actor had been testing on Turkish websites since September.

The attack illustrates the blast radius when a third-party A/B-testing or personalization vendor is compromised: a single point of injection reaches hundreds of organizations simultaneously, and each affected site's visitors become potential victims without that site doing anything wrong. The gap between the September test campaign and the November full deployment suggests deliberate reconnaissance. Optimizely has not disclosed how the initial compromise occurred.

Why it matters: Any client using a third-party web experimentation or tag-management platform should verify whether Optimizely is in their vendor stack and check their sites for indicators now. More broadly, PCI DSS 4.0.1's script-integrity and change-detection controls exist precisely for this scenario — if clients are treating them as checkbox items, this case makes the business case to operationalize them before year-end.

CriticalKEVDeserialization · RCE · MSP

Puppet Enterprise deserialization RCE (CVE-2026-115731, CVSS 9.4) added to CISA KEV; crypto miners deployed hours after proof-of-concept release

SecurityWeek and The Hacker News report that CISA added CVE-2026-115731 — a critical deserialization vulnerability in Perforce Puppet Enterprise and Puppet Core — to its Known Exploited Vulnerabilities catalog on November 17. The flaw allows clients holding CA-signed agent certificates to send malicious report payloads that execute with service-user privileges on the Puppet server, potentially exposing the certificate-signing key and enabling an attacker to issue trusted certificates for any managed host. Exploitation was first flagged November 4; Perforce released patches November 3. CISA's BOD 26-04 gives federal agencies two weeks to patch.

An independent proof-of-concept targeting the OpenVox configuration management platform (which shares the codebase) was published after the patch, and threat actors deployed cryptocurrency miners against N-able N-central servers using a chained exploit that includes this Puppet vector within hours. Affected versions span Puppet Enterprise 2026.0.1, 2025.12.1, and 2023.8.13, and Puppet Core 9.1.3 and 8.22.2. Organizations should disable auto-signing and enforce strong certificate validation in addition to patching; a compromised signing key requires rotating all managed-node certificates.

Why it matters: Puppet manages configuration at scale — a compromised Puppet server is a compromised fleet. Any client running configuration management on Puppet should treat this as a critical patch requiring same-day action, not the next maintenance window.

HighNation-state · FSB · Cloud

Russian COLD RELIC group used an entire cloud drive stolen from one U.S. organization to socially engineer its way into a second

Google's Threat Intelligence Group (Mandiant) published analysis showing that COLD RELIC — an FSB-linked group also tracked as ColdRiver — harvested admin credentials in an intrusion into a first U.S. organization in late 2025, downloaded the target's complete cloud drive, employee directory, emails, and personnel records, then used that authentic-looking material to impersonate employees over encrypted messaging and trick a second organization's staff into handing over Microsoft login credentials and authentication tokens. Google did not name either victim but described them as organizations in government-adjacent sectors. The group has operated since at least 2015 and was observed in new phishing campaigns as recently as November 2026.

The technique is a refinement of spear-phishing: by starting with a complete organizational dataset, attackers can construct lures that reference real internal names, projects, and relationships — far harder to dismiss than generic messages. The final step exploited a legitimate trusted-contact relationship to send malicious credential-harvesting links, then pivoted to cloud storage. The attack illustrates why a cloud breach is not just a data-loss event but also a dossier that enables the next campaign.

Why it matters: This chain — cloud breach → data harvesting → identity impersonation → second breach — shows why breach scope can't be assessed solely by what an attacker accessed. What they downloaded becomes the blueprint for follow-on targeting. Recommend clients with high-value cloud drives apply strict least-privilege access to bulk export, and treat out-of-the-blue messages from "colleagues" on encrypted channels with the same skepticism as cold email.

CriticalMSP · N-central · 0-day chain

N-able patches 17 N-central zero-days and kills legacy APIs after 4EverAble2Shell exploit chain lands crypto miners on MSP management servers

SecurityWeek reports that N-able released N-central 2026.4 Hotfix 3 patching 17 zero-days (CVE-2026-129271 through CVE-2026-129287) covering privilege escalation, missing authentication, command execution, RCE, XXE injection, SSRF, audit log tampering, and user enumeration. The most dangerous is the 4EverAble2Shell chain, which combines a legacy API flaw with CVE-2026-90436 (an Apache Axis RCE) to run commands with root privileges — threat actors deployed cryptocurrency miners using proof-of-concept code within hours of its November 12 disclosure. N-able permanently removed the legacy APIs in this update, eliminating the 4EverAble2Shell vector entirely. All on-premises deployments and their agents and probes must be upgraded for complete coverage.

Why it matters: N-central is the management plane for MSPs overseeing hundreds or thousands of endpoints. A compromised N-central server gives attackers authenticated access to every managed client. This is a same-day patch with no waiting for a maintenance window — treat it like a zero-day on a firewall.

BreachBusiness · Market research

Ipsos, the world's third-largest market research firm, is investigating a breach of an internal system; client and project data may be at risk

SecurityWeek reports that Ipsos went public with a breach of an unspecified internal information system on November 16, five days after filing a complaint with authorities. The company said it could not yet determine whether information relating to clients, projects, or business partners was affected, but committed to notifying any parties whose data was confirmed in scope. Ipsos stated the incident had no impact on operations or service delivery. No threat actor has claimed responsibility.

Ipsos conducts surveys and market research for major corporations, governments, and political campaigns worldwide. The sensitivity of its data — which can include confidential product plans, employee sentiment surveys, and proprietary consumer data for clients — makes it a target of distinct value to both financially and espionage-motivated actors. The scope of the breach remains under investigation.

Why it matters: Market research firms sit outside most vendor security programs because they are perceived as low-technical-risk suppliers. This case is a reminder that any firm handling confidential client data — survey instruments, internal questionnaires, strategic studies — deserves the same scrutiny as a software vendor with network access.
